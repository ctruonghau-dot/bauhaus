# BAUHAUS AI · 工作流设计说明

本文说明 BAUHAUS AI 如何把「一张服装照片」变成「一支约 24 秒的短片」：每一步做什么、为什么这样做、数据怎样流动、出错时如何兜底。使用方法见[使用说明](使用说明.md)。

---

## 1. 设计目标

| 目标 | 落到设计上 |
| --- | --- |
| 一张图就能出片 | 用户只提供一张商品照片，其余全部由系统推断和生成 |
| 衣服要像 | 商品原图作为每一张首帧的最高优先级参考；生成后逐项比对，差异大就打回重画 |
| 画面不穿帮 | 每张首帧都经过 GPT 质检，没通过的不会交去生成视频 |
| 有审美、不推销 | 采用“自然主义生活方式”的说话方式：画面讲生活，字幕讲商品 |
| 人始终可控 | 关键节点停下来等用户确认，确认后才继续、才花钱 |
| 简单可分发 | 纯本地运行：一个网页加一个只用 Python 标准库写成的小服务 |

---

## 2. 内容方法论：画面讲故事，文字讲商品

这一节是整个工作流的“导演意图”。它写在系统提示词（`SYS`）里，GPT 的每一次调用都会带上。

**画面**是一段安静的生活小故事：人、光、空气、季节、一个小动作。衣服是生活的一部分，而不是被摆拍的商品。观众通过看见面料、看见触摸、看见穿着状态，自己得出“值得拥有”的结论。

**字幕**不讲故事，也不抒情。它是一段平实的商品说明，拆成一屏一屏，跟着画面依次出现：

- 第一屏是品名，例如“皮草质感／短款外套”；
- 中间按面料 → 工艺细节 → 触感 → 版型的顺序，每屏只讲一个事实；
- 最后一屏落在穿着感受，例如“穿着温暖／行走自在”。

每屏两行，每行 4–9 个字，用说明书式的书面语。不用比喻，不用第二人称，不用感叹号和绝对化用语。

**事实纪律**：只写照片上看得见的事实，不编造成分、工艺和功能参数。触感与穿着感受可以由外观合理推出：比如长绒蓬起，可以写“蓬松柔软”；宽松短款，可以写“活动自在”。

**字幕跟画面**：手触摸面料的镜头讲触感，领口、袖口的近景讲工艺细节，侧身或行走的镜头讲版型，全景讲穿着感受。

这套方法参照了无印良品法兰绒衬衫影片的字幕结构。

## 3. 系统架构

```
┌──────────────────────── 浏览器（index.html） ────────────────────────┐
│ 界面与流程编排 · 确认关口 · 镜头跟随                                   │
│ 画布合成：视频 + 字幕 + 调色 + 混音 + 片尾卡 → MediaRecorder 录制成片  │
└──────────────┬───────────────────────────────────────────────────────┘
               │ 同源 HTTP（只接受本页面发出的请求）
┌──────────────▼──────────── 本地服务（server.py） ────────────────────┐
│ 保管密钥（keys.json） · 转发请求 · 视频中转 · 保存成片 · 静态资源       │
└─────┬───────────────────────┬──────────────────────┬─────────────────┘
      │                       │                      │
  OpenAI Responses       小云雀 / Seedance      Openverse
  GPT · GPT Image        2.0 Mini（首帧模式）   CC 授权配乐检索
```

为什么需要本地服务：

1. 小云雀接口不允许浏览器直接调用（受 CORS 限制）。
2. 密钥不能出现在网页里。
3. 第三方 CDN 上的视频直接画到画布上，会让画布无法录制。经过本地中转后，视频变成同源资源。
4. 长时间的生图请求如果走一条一直挂着的流式连接，会被中途掐断。所以生图改用“后台任务 + 轮询”：先提交，再每 4 秒查询一次结果。

合成在浏览器的画布上实时完成，不依赖 ffmpeg 等外部工具。

## 4. 流程总览

```
01 输入 → 02 理解 → 03 策划 ═▶ 04 分镜 ═▶ 05 首帧 ═▶ 06 生成 ═▶ 07 成片 → 首映
  本地       GPT        GPT        展示      GPT画+GPT查   小云雀    GPT + 画布
```

`═▶` 表示要等用户确认才继续。

| 步骤 | 执行者 | 输出 |
| --- | --- | --- |
| 01 输入 | 浏览器 | 压缩后的 JPEG（长边 1280）、6 色主色板 |
| 02 理解 | GPT（看图） | 商品理解 JSON，包含外观锁定描述 `garment_lock` |
| 03 策划 | GPT（看图） | 片名、创意、品名、五屏文案、人物造型、配乐方向、五个镜头的设计 |
| 04 分镜 | 浏览器 | 分镜板 |
| 05 首帧 | GPT Image + GPT 质检 | 五张通过质检的首帧，并已上传到小云雀；每镜的字幕位置 |
| 06 生成 | 小云雀 | 五段 5 秒、3:4 的视频 |
| 07 成片 | GPT（剪辑决策）+ 画布 | 约 24 秒的成片 |

## 5. 分步设计

### 02 理解

GPT 看商品照片，输出以下字段：

- **基础属性**：品类、一句画面感描述、颜色、面料推断（附置信度和依据）、廓形；
- **细节**：3–5 个可见细节，带图中坐标，用来在原图上打点标注；
- **策划素材**：性格词、季节、最自然出现的生活场景；
- **`unknowns`**：图片无法确认的属性，明确标出“不臆测，不写进文案”；
- **`garment_lock`**：一段 80 词以内的英文外观锁定描述。

`garment_lock` 必须写到“能被画出来”的程度：颜色与色调、长度、廓形、领型、袖口拼色与宽度、门襟、里布，以及面料表面的毛长（估计厘米数）、是蓬乱成簇还是顺滑平整、斑驳强弱、光泽、密度。描述里禁止使用 subtle、slightly 这类会弱化质感的词。

### 03 策划（确认关口一）

五个镜头沿着一条情绪弧线展开：

1. **环境与季节**：先进入一段生活，衣服可以只是画面的一部分；
2. **触摸**：手与面料自然接触，发生在一个生活动作里；
3. **穿着中的日常**：人物在做一件小事；
4. **动态中的细节**：风吹动面料、袖口随手臂移动；
5. **人在环境里**：全景或背影，安静收尾。

同一位人物贯穿全片。`model_look` 固定她的外貌和搭配，每个有人物的镜头都逐字复用这段描述。

每个镜头包含以下内容：

- 段落名、景别、机位；
- 中文动作描述；
- 本镜字幕；
- `frame_prompt`：英文首帧提示词，90–140 词。衣服只写 *the exact garment from the reference image*，并照抄 `garment_lock`；构图要为字幕留出干净的空白；
- `motion_prompt`：英文运动提示词，40–70 词。内容是从这一帧开始的 5 秒里，一个克制的动作、一种机位运动、一点环境里的微动。

此外还会输出品名、五屏文案，以及片尾卡的品名和一句收束。

### 04 分镜（确认关口二）

五张镜头卡依次翻入，每张显示时间码、景别、机位、动作和字幕。悬停可以查看运动提示词。

### 05 首帧（确认关口三）

**定妆帧先行**：先挑一个有人物的中景或近景镜头，画出“定妆帧”。它通过质检后，其余四镜并行绘制，并以它作为人物参考，保证五镜是同一个人、同一个世界。

**生图提示词的结构**：

1. **GARMENT REFERENCE — HIGHEST PRIORITY**：图一是商品原图，必须还原为同一件实物。颜色、真实尺度下的面料表面、长度、廓形、领型、袖口、门襟、里布全部一致。不得增删任何设计。忽略衣架、背景、吊牌，衣服上不能挂任何标签。最后附上 `garment_lock` 原文。
2. **定妆帧（如有）**：图二只用来参考人物、调色和环境；如果图二里的衣服和图一不同，以图一为准。
3. 本镜的 `frame_prompt` 与 `model_look`。
4. 风格与禁止项：真实的手、柔和自然光、低饱和胶片色、3:4，留白给字幕；不要文字、logo、水印、衣架、吊牌。
5. 如果是重画，附上上一轮的修改意见。

**质检**：GPT 同时看商品原图和这张首帧（如果有定妆帧，也一起看），输出：

- **逐项比对**：颜色、面料、毛向、衣长、廓形、领型、袖口、门襟、里布，每项判为一致、轻微偏差、明显不同或看不到；
- **`garment_score`**：0–10 的还原分；
- **其他穿帮**：手指与肢体、文字水印、logo、衣架吊牌、人物是否一致、空间逻辑；
- **字幕位置**：画面里最干净的留白（`caption_zone`），以及该处底色的明暗。

**判定规则**：

- 任何一项“明显不同”、还原分低于 7，或者出现明显穿帮，都判为不通过；
- 面料“一眼能看出不同”时，必须判为明显不同；
- 前后要自洽：在问题清单里提到的项目，不能同时判为一致；
- 不通过时，要用英文写出“原图里这一项应该是什么样”，作为下一轮的修改意见。

**轮次**：最多四轮。全程记录还原分最高的一张；四轮都不通过时，就用这一张。通过的首帧会上传到小云雀。

### 06 生成（确认关口四）

以首帧模式（`generate_type: 1`）提交：首帧图加上 `motion_prompt`，时长 5 秒，3:4。五镜同时提交，每 7 秒轮询一次状态，完成后经本地服务中转下载。

### 07 成片

**剪辑决策**：GPT 根据素材（每镜的段落、景别、字幕、位置、时长）、配乐候选和商品理解，输出：

- 每镜的入点和出点：保留 3.6–4.6 秒，避开首尾 0.2 秒；
- 五屏字幕的最终定稿：必须是商品说明，故事句要改写；
- 字幕位置：默认沿用首帧质检时找到的留白；
- 配乐的选择和理由；
- 片尾卡：品名和一句收束，时长 3.4 秒（范围 2.8–4.2 秒）；
- 调色参数：饱和度、对比度、冷暖。

**画布合成**：

- 分辨率 960 × 1280，帧率 30 帧/秒，由 Web Worker 驱动计时，避免掉帧；
- 第一镜的字幕是标题卡样式：品名稍大、加粗，下方是斜体英文片名；
- 每屏字幕出现前，先采样所在区域的亮度：默认白字带柔和阴影，只有底色很亮且几乎没有暗部时才用深色字；
- 最后一镜的最后 0.7 秒淡入片尾卡。片尾卡是纸色底，画面依次展开：一张剧照、竖排的品名、一句收束，以及 BAUHAUS AI 的印章。

**配乐**：

- 曲目来自 Openverse 检索的 Jamendo CC 授权器乐，优先选择可商用的授权。取不到时，在浏览器里现场合成一段氛围钢琴。
- 从曲子第一个明显有声的位置开始播放，1.4 秒淡入，最后 2.6 秒淡出。

**录制**：用 MediaRecorder 录制，优先 MP4（H.264 + AAC，10 Mbps）。录完进入首映页，同时保存到 `作品/`。

## 6. 人在回路：确认关口

| 关口 | 用户看到什么 | 确认后发生什么 |
| --- | --- | --- |
| 策划之后 | 创意、文案、风格资产 | 拆成五个镜头 |
| 分镜之后 | 五张镜头卡 | 开始画首帧（OpenAI 计费） |
| 首帧之后 | 五张首帧，以及质检结果和还原分 | 提交小云雀（约 100 积分） |
| 生成之后 | 五段视频 | 剪辑、字幕、配乐、录制 |

**交互的一致性**：

- 确认按钮永远固定在右下角，按回车也可以确认。
- 每次停下时，“已就绪”提示条停在离屏幕底边 190 像素的位置，让这一步的内容填满上方。
- 流程推进时，页面自动跟随当前步骤；用户手动滚动后暂停跟随 6 秒，点确认后恢复。

## 7. 容错与兜底

| 环节 | 策略 |
| --- | --- |
| GPT 文本调用 | 自动重试 1 次。仍失败时，该步骤显示“中断”和“重试”按钮，由用户决定 |
| 生图 | 后台任务加轮询，单次最长 5 分钟，失败重试 3 次 |
| 首帧彻底失败 | 依次退回：还原分最高的一张 → 商品原图本身 |
| 上传与提交 | 各重试 3 次，间隔递增 |
| 视频生成失败 | 如果还没有扣费，自动重新生成 1 次；已扣费就不再重抽 |
| 视频下载 | 重试 5 次，每次重新获取下载地址。本地服务在 Python 握手失败时会改用系统 curl，再试 4 次 |
| 视频彻底失败 | 用首帧做缓慢推镜代替，保证成片完整 |
| 配乐失败 | 依次尝试其余候选曲目，全部失败就现场合成钢琴 |
| 质检本身失败 | 放行，并标注“检查暂不可用” |

## 8. 演示模式

演示模式下不发出任何 GPT 或小云雀请求，请求函数会直接拒绝调用接口。无论放入什么图，都回放标杆样片《冬日买面包》的真实产出：

| 产出 | 来源 |
| --- | --- |
| 理解、策划、剪辑决策 | `demo/bench.json` |
| 首帧及每一轮的质检记录（含一次真实的打回重画） | `demo/f0–4.jpg` 与 `bench.json` 中的 reviews |
| 五段视频 | `demo/c0–4.mp4` |
| 配乐 | `demo/music.mp3` |

每一步的界面、节奏和确认关口都与工作模式一致。成片同样是在浏览器里现场合成、录制的。

## 9. 安全与隐私

- **密钥存放**：密钥只保存在本机的 `keys.json`，文件权限为仅本人可读写，并已被 `.gitignore` 排除。网页只能拿到“是否已配置”和密钥末四位。
- **测试连接**：只调用不计费的接口。
- **请求来源**：本地服务只监听 127.0.0.1，并且只接受本页面发出的请求，其他网站发来的请求一律返回 403。
- **静态文件**：只按文件名提供 `demo/` 与 `home/` 中白名单类型的文件，防止访问目录之外的内容。

## 10. 成本与耗时（每支片）

| 项目 | 量 |
| --- | --- |
| GPT 文本 | 3 次（理解、策划、剪辑） |
| GPT 生图与质检 | 各 5–20 次，取决于重画轮数 |
| 小云雀 | 5 镜 × 5 秒，约 100 积分 |
| 首帧耗时 | 约 3–8 分钟：定妆帧先画，其余并行 |
| 生成耗时 | 约 2–5 分钟，五镜并行 |

## 11. 可扩展点

- **镜头数与片长**：分镜数量、每镜保留时长、片尾长度，都集中在策划和剪辑的提示词里。
- **固定主角**：可以加入一张模特三视图作为人物参考，提高跨片子的人物一致性。
- **生成后质检**：在视频生成后再比对一次截帧，不合格就重新生成（会增加积分消耗）。
- **视频模型**：在「API 设置」里直接更换模型名。

---

## 12. 已知局限

- 复杂面料（长毛、强斑驳）在生图和视频里都可能被画得偏顺滑。商品原图越清晰，效果越好。
- 首帧到视频之间仍可能有轻微走样。
- 成片依赖浏览器实时渲染录制，录制期间页面需要保持在前台。
- 文案只基于一张照片，写不出成分、工艺等看不见的信息。
